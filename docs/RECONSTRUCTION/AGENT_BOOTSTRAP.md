# Any-Shape — cold reconstruction charter

This earlier browser charter is retained as historical specialization. Handoff 002's universal mission and [COLD_START_RECONSTRUCTION](COLD_START_RECONSTRUCTION.md) now govern the neutral reconstruction protocol. Do not define the project solely by shape/overflow.

For a current blind trial, use the semantic-only canonical projection and allowlisted new identity documents produced by `scripts/create-reconstruction-bundle.py`; keep original mechanism/evidence records with the evaluator. The legacy paragraph below names full foundation/model inputs that can reveal implementation context; do not use that unfiltered selection as a strict blind bundle. Shared-host procedural restrictions do not establish enforced isolation.

## Purpose, without naming implementation tools
Any-Shape preserves comprehensible information hierarchy, useful interaction, legibility, accessibility and recognizable visual identity while the space available to an interface and the user's environment change. Rearrangement is allowed and expected; loss of meaning is not. It is an adaptive interface system, not a breakpoint table, screenshot clone, framework, or runtime dependency.

## Formal blind reconstruction
A genuinely new agent MUST receive only the Forever Works model in `forever/`, `docs/FOUNDATION/PURPOSE.md`, `docs/FOUNDATION/CONTRACTS.md`, and `docs/RECONSTRUCTION/CONFORMANCE_SPEC.md`. It MUST NOT see `src/`, current examples, package metadata, original test implementations, screenshots, implementation reports, commit history or original source code. A separate evaluator retains those for later comparison. Clearly disclose if isolation is broken. If API drop-in compatibility is required, provide a separately prepared *interface contract* rather than source.

## Before writing code
1. Explain purpose in plain language without CSS/JavaScript/TypeScript names.
2. Enumerate capabilities, invariants, constraints, stakeholders, inputs/outputs, exceptions, tradeoffs and unknowns.
3. Build an intent → capability → invariant → independent test traceability table.
4. Identify choices that are mechanisms versus requirements; do not inherit the original technology stack reflexively.
5. Choose a language and architecture; browser-delivered HTML/CSS output is permitted even when the authoring implementation is Python, C, C++, Rust, Go or another language.
6. Treat `agent-proposed` intent as pending owner confirmation; no automatic promotion to accepted truth.

## Observational equivalence
A replacement need not reproduce CSS selectors, breakpoints, exact pixels or algorithms to be semantically equivalent. It MUST preserve: hierarchy and content relationships; locally container-sensitive layout; action reachability; keyboard and form semantics; accessible and readable narrow/zoomed/long-text presentation; graceful feature fallback; privacy-respecting explanation of failures. The intended aesthetic must receive human review because screenshots alone cannot prove beauty.

## Inputs, environments and stress
Construct a neutral fixture: header, navigation, grouped cards, labeled form with a selector and submission, disclosure, two concurrent instances of the same component in unequal containers, and 3 deliberately faulty layouts. Test across 280px through ultrawide widths, portrait/landscape, changing container width at constant viewport, enlarged text, 200% and 400% zoom-equivalent reflow, long translated strings, RTL, reduced motion, keyboard, no-JS baseline, missing optional layout enhancement, and missing diagnostic module. Do not hardcode success against just the sampled viewports.

## Independent implementation evidence
Produce: source and reproducible build; explicit language and output boundary; completed intent-to-test table; structured report for AS-001…AS-016 with observed measurements, environment, pass/fail/unknown and references; visual review separate from automatic geometry checks; compatibility mapping; dependency inventory; controlled loss/replacement exercise; retrospective identifying any underspecified requirement.

## Meaning of victory
A validated JSON manifest is merely a verified *model format*. A running replacement is not a proof of equivalence until independent tests execute. Cross-language portability is demonstrated only for languages/architectures actually reconstructed. Never claim universal portability from a single test. Any candidate behavior not covered by existing records must be identified as an extension, not silently presented as original project meaning.
