# Cold-start reconstruction handbook

For an independent inheritor with no original source, frameworks or history. The explicit universal mission governs meaning; all technical examples retain their declared proposal status.

## Inputs and isolation

Receive neutral essence, ontology, coordinated-face, transformation/accessibility, cross-medium and conformance documents; semantic-only canonical intent/capability/invariant/constraint records; independent fixture data; and separately declared external interface contracts if drop-in compatibility is required. Do not receive mechanism descriptions, old source/examples/tests/screenshots, package metadata, implementation reports or Git history. A separate evaluator retains the old product.

The current trial started with three neutral meaning documents, a semantic-only canonical projection and the preferences fixture. Additional neutral AS stimuli were supplied later. The committed inventory records initial/supplement hashes and exclusions. This is a procedural blind trial on a shared host, **not an isolation-guaranteed clean room**. A strict trial MUST enforce a separate container/machine and filesystem mount allowlist, strip Git metadata/history and deny original artifact/network access; instruction alone does not provide that guarantee.

Use `python3 scripts/create-reconstruction-bundle.py OUTPUT` to build a neutral bundle for a future trial. Audit its contents manually before releasing it; references/citations are not permission to read withheld files. A bundle manifest is source provenance, not evidence that an agent obeyed an unenforced restriction.

## Before code

1. Explain Any-Shape's universal purpose without defining it as browser resizing.
2. Enumerate actors, logical surfaces/fields/objects/actions, invariants, constraints, success, failure and unsupported states.
3. Separate explicit owner statements from inferred mappings and proposed technical details.
4. Build a mission → capability → obligation → independent observation matrix.
5. State your target medium, authoring language, available input/renderer facilities and unsupported scope.
6. Choose a different source architecture; generated browser output is allowed and does not erase a Python/Go/Rust authoring distinction.
7. Record assumptions needing host/owner decisions rather than inventing accepted authority policy.

Write understanding before implementation. An evaluator reviews it for semantic correctness, but running tests are still needed for runtime claims.

## Rebuild procedure

Implement the smallest domain model that can execute the neutral fixtures: stable IDs, field validators, a state transition boundary, host authority/consent checks, typed errors and a read/discovery surface. Add a human adapter and an agent adapter that call the same domain logic. Domain code MUST NOT depend on coordinates or a decorative renderer. Start with the supported baseline; then implement transformations and fallbacks.

Create independent samples for unequal local contexts, text expansion, constrained geometry, alternative direction/input, missing enhancement and deliberately broken cases. Use semantic targets, not the original class names. Optional diagnostics must distinguish measurements, authored declarations and hypotheses and remain privacy-safe. Decide whether a target supports a given operation; explicit unsupported state is more honest than fictitious parity, but may still fail a required scope.

Register dependencies with purposes, classification, protected requirements, replacements and proof plans. A language runtime or renderer is a mechanism; logical identity/authorization meaning is a commitment. Test functional readiness with actual requests/operations, not a PID or build exit alone.

## Independent evaluation and migration

Hand only public entrypoints/target IDs to a separate evaluator. It uses frozen fixture expectations and actual outputs without copying old assertions or candidate self-tests. Evaluate semantic/function, access, aesthetics and drop-in compatibility separately. Preserve initial failures and scope gaps before improvement. A new fixture/stimulus supplied later must be recorded as a supplement, not pretended to be part of the original sealed input.

Physically remove an optional artifact in scratch and rerun independent operations. Replace a development harness and disclose the driver/runtime still retained. Connect those observations to canonical dependency/candidate/migration records. Do not declare total reconstruction or universal language portability from a scoped example.

Where drop-in compatibility is required, receive the interface contract separately, implement an adapter or issue a migration report, and test an actual consumer. If the candidate cannot supply the documented CSS/ESM/schema boundary, report that lane unknown or fail as warranted. Keep the old product available; do not adopt the proof automatically.

## Evidence and maintenance

Record source/output hashes, commands, environment versions, inputs, actual observations, test counts and PASS/FAIL/UNKNOWN. Keep artifacts synthetic/redacted. Run the actual pinned Forever Works CLI validate/audit, independent published-schema checks, replacement evaluation and migration verification. Inspect findings; audit exit zero is not an issue-free model. Never weaken schemas or fabricate implementation records merely to erase proposal gaps.

Finish with reproducible source, understanding, dependency inventory, compatibility mapping, tested/untested targets and remaining owner questions. Commit evidence before changing the implementation again. A future agent repeats the observations; predecessor confidence is not proof.

## Undecidable from current evidence

Production authentication/consent durability, distributed consistency, large-data completeness/resource thresholds, native desktop/3D accessibility, aesthetic approval and platform snapshot restoration remain unresolved until their scope and evidence exist. Ask for genuinely required host/owner decisions after useful independent work; technical serialization does not answer them.
