# Dependency and failure atlas

Maintainer/evaluator lane; exclude mechanism details from blind input. `forever/dependencies/` records purposes and replacement obligations; `docs/DEPENDENCIES.md` retains exact existing development versions/licenses. Classifications are canonical Forever Works values, not informal synonyms.

## Foundational semantics versus mechanisms

Stable logical identity, shared domain validation, authority boundaries and honest unsupported states are semantic commitments. Their implementation language, toolkit, storage and transport are replaceable. A capability classification does not authorize changing the protected behavior. The web CSS/ESM/schema boundary is currently a SEMANTIC compatibility obligation; source language is not locked. No named agent vendor is foundational.

| Dependency | Classification / purpose | Disappearance and recovery | Required proof |
|---|---|---|---|

| Browser HTML/CSS facilities | SEMANTIC in web scope; accessible realization | Retain simple web baseline, or choose a different supported medium with explicit migration | AS conformance plus API compatibility or declared incompatibility |

| TypeScript | CAPABILITY; declaration validation | Compatible checker or downstream consumer validation; plain runtime output stays usable | Public type consumer and errors; JS evidence is separate |
| Ajv/schema tool | CAPABILITY; canonical format checks | Another draft-2020-12 implementation over pinned actual schemas | Both valid/invalid corpus, graph checks and preserved unknown fields |

## Controlled exercise protocol

1. Read the dependency's protected capability/invariant/compatibility IDs using the canonical CLI `explain` and `trace`.
2. Record the exact baseline artifact, implementation scope and tests expected to run.
3. Copy only task-created artifacts into scratch; remove the named dependency artifact physically. Do not delete the original application or user work.
4. Start the fallback/replacement and make functional requests or transitions. A successful import, open port or prose claim is insufficient.
5. Evaluate unchanged obligations with an independent harness. Capture raw outcomes and any reduced coverage.
6. Register observed evidence and candidate claims. Evaluate replacement and migration separately; absent claims are unknown and unmet compatibility can fail.
7. Keep old implementation available until a reviewed migration and rollback policy permit adoption. Cleanup only scratch/processes created for the exercise.

## Concrete failure reproduction

For the established package, `npm run test:recovery` removes diagnostic code in scratch and exercises layout/form/accessibility with Node assertions. Its original report is historical; current task reruns it. It replaces the test-runner harness while retaining the browser driver, and does not prove driver independence.

For the proof, run `node scripts/evaluate-reconstruction.mjs`. The evaluator uses public candidate instructions to remove optional artifacts and exercise outcomes; it does not read candidate assertions. The report names removed artifacts, fallback requests and status. The canonical proof dependency and candidate records connect that evidence to requirements. Do not replace actual disappearance with setting a cosmetic flag and call it the same exercise.

If the browser binary cannot start, diagnose libraries/profile isolation separately from product failures. On this host use the documented retained rootless browser cache and sandbox exception. If the standard cannot be fetched, the vendored upstream pin is usable; if its hashes disagree, stop treating it as authentic until restored from trusted source. Never disable TLS, signatures, expected checksums or assertions to produce a pass.

## What these exercises do not prove

They do not replace an entire OS, browser driver, authentication stack, large-data engine or 3D renderer. No unmeasured memory/GPU budget is asserted. A proof's fixture actors are not secure production identities. A fallback demonstrating read access cannot prove write preservation. These distinctions MUST survive future inheritance.
