# Project essence

## Enduring purpose — explicit owner mission

Any-Shape enables information and operations to remain comprehensible, accessible, attractive where practical, and functionally available to humans and programmatic agents as medium, geometry, constraints, input methods and computational resources change. **The form may change; meaning, essential functions and trustworthiness must remain.** This mission is explicit in handoff 002. Serialization does not authorize an agent to enlarge it further.

The project serves people using interfaces, agents acting within delegated authority, interface authors, adopters, evaluators and future maintainers. A person may recognize an object through a visual hierarchy; an agent may identify it through a stable record. Both encounter the same domain object, permissible actions, validation and state. A new representation may reorganize interaction without inventing a different meaning.

## Obligations and boundaries

An Any-Shape realization MUST identify its supported scope and preserve essential information, relationships and authorized operations within that scope. It MUST expose unavailable operations and resource limitations honestly. It MUST NOT exchange accessibility or permission checks for a more attractive rendering. Human aesthetics are a design goal where meaningful, not an automatic universal score. A text interface can preserve function without matching a visual medium's ornament; this is an explicit change in presentation, not proof of identical experience.

Browser resizing is one useful demonstration, not the identity of the project. Other allowed realizations include desktop windows, paged text, agent protocols and 3D editor surfaces. Allowance is not support certification: a target becomes demonstrated only after independent evidence. A renderer, authoring language, toolkit, transport or agent provider MAY be replaced while the behavioral obligations and declared compatibility boundary survive.

The project refuses to become a pixel-cloning mandate, a device breakpoint taxonomy, an automatic beauty oracle, a proprietary agent service, or a promise of equivalence in every possible medium. It does not invent domain authorization policies for adopters. It does not grant an agent authority because an operation is discoverable.

## Victory and counterexample

Winning requires three separate judgments: a cold inheritor correctly understands the meaning; a new realization preserves tested semantic/function/access obligations under transformations; and any required historical API boundary is preserved or honestly migrated. Passing a JSON schema is format evidence only. Running a renderer is availability evidence only. A screenshot is an observation, not proof of operation or aesthetic quality.

Example failure: a narrow view hides the only submit operation while an agent endpoint still changes the state. This loses human operation and parity even if the screen looks tidy. Expected outcome: reflow, staged navigation or an explicit alternative retains the submit action and its validation; both channels reach the same authoritative state. If the medium cannot support the action, it reports that limit and a feasible deferred route rather than claiming equivalence.

The universal mission is accepted as explicitly instructed. Detailed ontology, transport names, example data, retry rules and thresholds in this documentation are **agent-proposed, unreviewed technical specifications** unless specifically attributed otherwise. MUST/SHOULD/MAY inside those proposals define candidate conformance, not silently ratified product policy.
